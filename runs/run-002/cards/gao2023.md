# 證據卡：gao2023（RAG Survey）— v2
- E1: LLM 的挑戰：幻覺、知識過時、推理過程不透明且無法追溯；遇到超出訓練資料或需要最新資訊的問題時特別容易產生「幻覺」。[wiki: concepts/llm-knowledge-limits.md] [src: gao2023, p.1]
- E2: 引用外部知識能有效減少產生事實錯誤內容的問題，也能持續更新知識。[wiki: concepts/llm-knowledge-limits.md] [src: gao2023, p.1]
- E3: 基本流程三步：索引（切成小塊、用 embedding 模型編碼成向量、存進向量資料庫）→ 檢索（用同一個編碼模型把問題轉成向量、算相似度、取 top-K 片段）→ 生成（問題＋片段組成 prompt 交給 LLM）。〔限定：Naive RAG〕[wiki: concepts/rag-paradigms.md] [src: gao2023, p.3]
- E4: 最常見的做法是以固定 token 數切分，例如 100、256、512；大塊能保留較多脈絡但雜訊多、處理時間與成本較高，小塊雜訊少但可能傳達不了必要的脈絡。〔限定：固定 token 數〕[wiki: concepts/chunking.md] [src: gao2023, p.8]
- E5: 檢索靠計算問題與片段 embedding 的相似度（例如 cosine similarity）；BM25 歸為 sparse、BERT 類歸為 dense，兩者捕捉不同的相關性特徵，可以混合（hybrid）互補。[wiki: concepts/retriever.md] [src: gao2023, p.9]
- E6: 三種範式：Naive RAG（Retrieve-Read）、Advanced RAG（加上檢索前與檢索後的策略）、Modular RAG（可新增、替換、重組模組，包含迭代與自適應檢索）。[wiki: concepts/rag-paradigms.md] [src: gao2023, p.3-4]
- E7: 論文比喻：RAG 像給模型一本量身訂做的教科書來查資料；fine-tuning 像學生隨時間把知識內化。〔限定：Gao et al.〕[wiki: comparisons/rag-vs-fine-tuning.md] [src: gao2023, p.5]
- E8: RAG 可即時更新、擅長精確查找資訊；fine-tuning 更新要重新訓練，擅長複製特定結構、風格或格式；兩者不互斥，可以互補。[wiki: comparisons/rag-vs-fine-tuning.md] [src: gao2023, p.5]
- E9: LLM 現在能處理超過 200,000 tokens 的脈絡，過去靠 RAG 的長文件問答，現在可以把整份文件直接放進 prompt。〔限定：長文件問答〕[wiki: comparisons/rag-vs-long-context.md] [src: gao2023, p.14]
- E10: RAG 仍需要的理由：一次給大量脈絡會明顯拖慢推理速度；RAG 能快速找到原始出處讓使用者驗證，過程可觀察；只靠長上下文的生成像黑盒子。[wiki: comparisons/rag-vs-long-context.md] [src: gao2023, p.14]
- E11: Gao et al. 引述 Cuconasu et al.：加入不相關文件反而可能讓準確率提升超過 30%，與原本假設相反。〔限定：引述 Cuconasu〕[wiki: comparisons/rag-vs-long-context.md] [src: gao2023, p.14]
- E12: Reranking 把最相關的片段排到前面、縮小文件池，同時有「增強」與「過濾」兩種作用。[wiki: concepts/reranking.md] [src: gao2023, p.10]
- E13: Naive RAG 的問題：檢索可能選到不相關片段、漏掉關鍵資訊；生成可能出現檢索內容不支持的幻覺；整合多段資訊可能不連貫或重複。〔限定：Naive RAG〕[wiki: concepts/rag-paradigms.md] [src: gao2023, p.3]
