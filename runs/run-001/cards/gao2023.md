# 證據卡：gao2023（RAG Survey）
- E1: LLM 的挑戰：幻覺、知識過時、推理過程不透明且無法追溯；遇到超出訓練資料或需要最新資訊的問題時特別容易產生「幻覺」。[wiki: concepts/llm-knowledge-limits.md] [src: gao2023, p.1]
- E2: 引用外部知識能有效減少產生事實錯誤內容的問題，也能持續更新知識。[wiki: concepts/llm-knowledge-limits.md] [src: gao2023, p.1]
- E3: 基本流程三步：索引（清理成純文字、切成小塊、用 embedding 模型編碼成向量、存進向量資料庫）→ 檢索（用同一個編碼模型把問題轉成向量、算相似度、取 top-K 片段）→ 生成（問題＋片段組成 prompt 交給 LLM）。[wiki: concepts/rag-paradigms.md] [src: gao2023, p.3]
- E4: 切塊最常見以固定 token 數切分，例如 100、256、512；大塊脈絡多但雜訊多、成本高，小塊雜訊少但可能脈絡不足。[wiki: concepts/chunking.md] [src: gao2023, p.8]
- E5: 檢索靠計算問題與片段 embedding 的相似度（例如 cosine similarity）；BM25 屬 sparse、BERT 類屬 dense，可以混合互補。[wiki: concepts/retriever.md] [src: gao2023, p.9]
- E6: 三種範式：Naive RAG（Retrieve-Read）、Advanced RAG（加檢索前與檢索後優化）、Modular RAG（可新增、替換、重組模組，含迭代與自適應檢索）。[wiki: concepts/rag-paradigms.md] [src: gao2023, p.3-4]
- E7: 論文比喻：RAG 像給模型一本量身訂做的教科書來查資料；fine-tuning 像學生隨時間把知識內化。[wiki: comparisons/rag-vs-fine-tuning.md] [src: gao2023, p.5]
- E8: RAG 可即時更新、可解釋性高但延遲較高；fine-tuning 更新要重訓，適合複製特定結構、風格或格式；兩者可以互補。[wiki: comparisons/rag-vs-fine-tuning.md] [src: gao2023, p.5]
- E9: LLM 能處理超過 200,000 tokens 的脈絡，引發「還需不需要 RAG」的討論。[wiki: comparisons/rag-vs-long-context.md] [src: gao2023, p.14]
- E10: RAG 仍需要的理由：一次塞大量脈絡會拖慢推理；RAG 能找到原始出處讓使用者驗證，過程可觀察，長上下文生成像黑盒子。[wiki: comparisons/rag-vs-long-context.md] [src: gao2023, p.14]
- E11: 論文引述的研究：加入不相關文件反而可能讓準確率提升超過 30%，與原本假設相反。[wiki: comparisons/rag-vs-long-context.md] [src: gao2023, p.14]
- E12: Reranking 把最相關的片段排到前面、縮小文件池，有增強與過濾兩種作用。[wiki: concepts/reranking.md] [src: gao2023, p.10]
- E13: Naive RAG 的缺點：可能選到不相關片段或漏掉關鍵資訊、生成檢索內容不支持的幻覺、整合多段資訊不連貫或重複。[wiki: concepts/rag-paradigms.md] [src: gao2023, p.3]
