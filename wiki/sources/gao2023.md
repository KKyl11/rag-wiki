# Gao et al. 2023 — RAG Survey

## 書目
- Yunfan Gao 等人（同濟大學、復旦大學），arXiv 2312.10997v5，2024-03-27 版。[src: gao2023, p.1]

## 一句話摘要
整理 100 多篇 RAG 研究，把 RAG 的演進分成 Naive、Advanced、Modular 三種範式，並分別檢視檢索、生成、增強三個核心環節與評估方法。[src: gao2023, p.1]

## 核心主張
- LLM 面臨幻覺、知識過時、推理過程不透明且無法追溯等挑戰；RAG 透過引入外部資料庫的知識來回應這些問題。[src: gao2023, p.1]
- RAG 透過語意相似度從外部知識庫檢索相關片段，引用外部知識能有效減少產生事實錯誤內容的問題。[src: gao2023, p.1]
- 典型 RAG 流程有三步：索引（切塊、編碼成向量、存進向量資料庫）、檢索（依語意相似度取 top-k 片段）、生成（問題＋片段一起交給 LLM 回答）。[src: gao2023, p.3]
- 三種範式：Naive RAG 是「Retrieve-Read」；Advanced RAG 加上檢索前與檢索後的優化；Modular RAG 可替換、重組模組，支援迭代與自適應檢索。[src: gao2023, p.3-4]
- 本文整理的評估涵蓋 26 種任務、近 50 個資料集。[src: gao2023, p.2]

## Naive RAG 的缺點
- 檢索：precision 與 recall 不足，選到不相關片段或漏掉關鍵資訊。[src: gao2023, p.3]
- 生成：可能產生檢索內容不支持的幻覺，也可能有不相關、有毒或偏誤的輸出。[src: gao2023, p.3]
- 增強：整合多段資訊可能不連貫或重複；只用原始問題檢索一次可能不夠。[src: gao2023, p.3]

## RAG vs Fine-tuning
- 論文的比喻：RAG 像給模型一本量身訂做的教科書來查資料；fine-tuning 像學生隨時間把知識內化。[src: gao2023, p.5]
- RAG 適合動態環境、可即時更新、可解釋性高，但延遲較高；fine-tuning 較靜態，更新需重訓，適合複製特定結構、風格或格式。[src: gao2023, p.5]
- 論文引述的研究發現：在知識密集任務上，RAG 一致優於非監督式 fine-tuning，LLM 也很難透過非監督式 fine-tuning 學到新事實。[src: gao2023, p.5]
- 兩者不互斥，可以互補。[src: gao2023, p.5]

## 檢索與後處理
- 切塊最常見的做法是以固定 token 數切分（例如 100、256、512）；大塊脈絡多但雜訊多，小塊雜訊少但可能脈絡不足。[src: gao2023, p.8]
- 片段可以附加 metadata（頁碼、檔名、作者、時間戳）以便過濾檢索範圍。[src: gao2023, p.8]
- 檢索靠計算問題與片段 embedding 的相似度（例如 cosine similarity）；包含 sparse（BM25）與 dense（BERT 類）兩類，兩者可混合互補。[src: gao2023, p.9]
- 多餘資訊會干擾生成，過長的脈絡可能造成「Lost in the middle」問題：LLM 傾向只注意長文的開頭與結尾。[src: gao2023, p.10]
- 重新排序（reranking）把最相關的片段排到前面，同時有增強與過濾的作用。[src: gao2023, p.10]
- 常見誤解是「檢索越多文件、串成越長的 prompt 越好」；過多脈絡會帶來雜訊。[src: gao2023, p.10]

## 評估
- 品質分數包含脈絡相關性（context relevance）、答案忠實度（answer faithfulness）、答案相關性（answer relevance）。[src: gao2023, p.12]

## RAG vs 長上下文、穩健性
- 現在的 LLM 能處理超過 200,000 tokens 的脈絡，引發「還需不需要 RAG」的討論。[src: gao2023, p.14]
- 論文認為 RAG 仍不可取代：一次塞大量脈絡會拖慢推理；RAG 能快速定位原始出處，讓檢索與推理過程可觀察，長上下文生成則像黑盒子。[src: gao2023, p.14]
- 論文引述的研究發現：加入不相關文件反而可能讓準確率提升超過 30%，與原本假設相反。[src: gao2023, p.14]
